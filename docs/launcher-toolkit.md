## 本体との連携

履歴・OBS・Discord設定・ランチャーからのリプレイ再生には、対応するTaikoDive本体の変更が必要です。
起動後の `Info/launcher-capabilities.json` はプロトコルバージョン1の対応情報です。
本体を初めて更新したときは通常起動を一度行うと、対応情報が作られます。

- 設定: `Info/TaikoDiveLauncher/integrations.json`。次回本体起動から反映。
- コーデ: `Info/TaikoDiveLauncher/outfits.json`。共有ファイルにはモデル本体を含めません。
- 履歴: `Info/TaikoDiveLauncher/history/*.json`。対応版で完走し、通常成績の保存条件を満たした演奏を記録。過去のScore.dat更新日時から回数は推定しません。
- OBS: `Info/TaikoDiveLauncher/overlay/index.html` をOBSのブラウザーソースで「ローカルファイル」として指定します。幅1280・高さ320程度を目安に調整できます。
- OBSは同じフォルダーの `status.js` を1秒ごとに読み込みます。別プロセスの常駐やHTTPサーバーは不要です。状態が5秒更新されなければ曲名等を消します。
- Discordは既定で無効。状態だけの公開と、曲名・難易度を含む公開を選べます。
- リプレイ再生は `--launcher-replay <best.json> --user-slot <1..9>`。本体でもユーザー、保存場所、譜面ハッシュを再確認します。

## 更新・復帰

本体・Assetの暗号化パッケージは、配信マニフェストのSHA-256をキーにキャッシュします。
HTTP Range対応なら途中から再開し、非対応なら最初から取得します。
サイズ・SHA-256と既存の暗号化パッケージ検証を通ったファイルだけを適用します。

更新履歴は適用先フォルダーごとに表示し、最後の未復帰の更新から順に戻せます。
追加ファイルを削除し、変更・削除ファイルをバックアップから復元します。
設定・スコア等の保護対象は更新・復帰の対象外です。
更新後に対象ファイルへ行った独自変更も復帰で戻るため、実行前に確認します。
バックアップは容量整理では削除しません。7日以上前のダウンロードと一時ファイルだけを整理します。

配布スクリプトの `MinimumGameVersion` / `MinimumAssetsVersion` / `MinimumLauncherVersion` で必要な最低バージョンを指定できます。
未指定の旧マニフェストは引き続き使えますが、未指定であることは互換性の保証ではありません。

## 診断・データ保護

診断レポートは保存前に本文を表示します。画面・音声の設定と最近のエラーログを含み、プロフィール・スコア・入力割当・接続先の設定は含みません。
ログ中のWindowsパス、URL、IPv4アドレス、実行ユーザー名を伏せますが、共有前に本文を確認してください。自動送信は行いません。

コーデの取り込みは1MB・100件まで。形式・色・IDを検証し、共有ファイルでモデルの参照先を変更しません。
素材不足のコーデは一覧に保存できますが、適用できません。読み込んだコーデはプレビュー確認後に既存の保存操作で反映します。

## 検証範囲

ロジックのテストに加え、WindowsでのWinUIビルドと実画面確認が必要です。
ライト・ダーク・ハイコントラスト・狭い幅で、各画面を確認してください。
音声試聴、Discordアプリへの実接続、OBSのローカルファイル表示、実ゲームのリプレイ起動、配信パッケージの適用・復帰はWindows環境での確認対象です。
